# Player behavior

This document describes the features present in the current application.

## Library

Kolo scans these folders under `kolo.0.data`: `pos`, `downloads/OLD`, `discovery`, `imported`, `neg`, and `playlists/<slug>`. The negative partition is hidden from the normal sidebar unless excluded playlists are enabled.

Track title and artist are derived from filenames in `Artist - Title` form. The player hides a trailing YouTube video id (`Song-dQw4w9WgXcQ`, `Song [dQw4w9WgXcQ]`) and trailing tags made only of video words, such as `(Official Music Video)` or `[Lyrics]`; tags with other words, such as `(from Moana / Official Video)`, are kept. Files are not renamed. The Vite backend can also load extracted artwork, cluster labels, loudness data, and model ratings from `.kolo`. The Tauri scanner currently provides the core filename, rating, like, and model-score fields.

Users can:

- search by title or artist;
- sort by title, modification date, personal rating, model rating, or duration;
- filter by personal rating and the configured model-score threshold; each filter chip shows how many songs it would leave;
- browse all tracks by an artist;
- create a playlist and import local audio files;
- add a YouTube URL or import a Spotify track, album, or playlist.

## Playback

Playback uses one HTML audio element so the web and desktop shells share the same controls. The player supports:

- play, pause, previous, and next;
- seek and elapsed/remaining time;
- volume and mute;
- shuffle;
- repeat off, repeat queue, and repeat one;
- a visible queue panel, split into the playing song and what plays next;
- automatic advance when a track ends;
- operating-system media keys and media overlays through the Media Session API.

Clicking the artwork or title in the player bar opens the list the song is playing from and scrolls to it.

## Keyboard shortcuts

Shortcuts work anywhere except while typing in a text field. They use physical key positions, so they also work with a non-Latin keyboard layout. Press `?` in the app for the full list.

| Keys | Action |
| --- | --- |
| Space | Play or pause |
| ← / → | Seek 5 seconds |
| Shift + ← / → | Previous or next song |
| ↑ / ↓ | Volume |
| 1–5 | Rate the playing song |
| Shift + 1–5 | Rate half a star less (Shift + 5 is 4.5) |
| 0 | Clear the rating |
| L | Like or unlike the playing song |
| M / S / R / Q | Mute, shuffle, repeat, queue |
| / or Ctrl + K | Search |
| Esc | Clear search, close the queue, dialogs, and menus |

When loudness normalization is enabled, Kolo applies the stored gain for the current track so every track plays at about -14 LUFS. Loud tracks are attenuated and quiet tracks are boosted by up to 12 dB. A boost uses the headroom between the volume slider and full volume, so at very high slider positions the quietest tracks are boosted less. The Vite backend measures new tracks on import and scans for unmeasured tracks at startup.

## Ratings and predictions

Personal ratings use a 0.5–5.0 scale. Likes are stored independently. Both are written to JSON immediately.

For unrated tracks, the latest regression estimate can be shown as gray stars. The estimate is a ranking aid and is visually distinct from a user rating. The “vibe filter” hides scored tracks below a configurable threshold while leaving unscored tracks visible.

## Taste map

The Taste Universe view embeds a generated Plotly document. It supports 3D t-SNE and UMAP views and title search. Coordinates and labels are generated by `kolo.1.eda/regenerate_clusters_and_viz.py`; the player does not fit clusters at runtime.

## Persisted state

The browser stores accent color, volume, loudness-limiter state, sidebar state, hidden-playlist visibility, and filter preferences in local storage.

Playback state survives a restart too: the current song and its position (saved about once a second and when the app closes), the queue with its source playlist and unshuffled order, shuffle, and repeat mode. The song comes back paused. The open playlist, sort order, rating filter, artist filter, and queue panel are restored as well. If the remembered song or playlist was deleted in the meantime, Kolo falls back to the default song or Home.

## Intentional limits

- Kolo is a local, single-user application; there are no accounts or cloud sync.
- Downloads and embedding extraction require external programs and network access.
- The Tauri shell does not contain a native audio engine or an embedded model runtime.
- Spotify import uses Spotify metadata to search for matching audio; it is not Spotify playback.
